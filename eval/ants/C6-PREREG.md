# C6 pre-registration — fetched voices (VOICE.md stage 5)
Written 2026-10-06 BEFORE any page was fetched and before `fold-chat-fetchedvoice.js` existed. Battery + hand labels: `eval/ants/c6/battery.json` (20 pairs: 10 own-words, 10 traps; 19 distinct URLs, T10 re-uses G4's URL under a different person).

## The classifier (mechanical only; no model)
`classifyPage({ person, url, html|text, title })` → `own` | `unsure` | `refuse` + typed reasons + standing. Features:
* **host class**: fold-chat-primary.js `kindOf`, `MIRROR_HOSTS`, `ENCYCLOPEDIAS`, fold-chat-tertiary `isTertiary`, plus a declared quote-farm host list (brainyquote, goodreads, azquotes, quotefancy, wikiquote, quotes.net, quotationspage, thinkexist, keepinspiring, quotegarden, brainyquote). Dropped kinds (farm/qa/social/mirror/encyclopedia/tertiary/quote-farm) → refuse.
* **title cues** (secondary-genre titles): "what would X say/think/do", "N (best|top|famous) ... quotes", "wisdom|lessons|teachings of/from", "for modern life" → refuse.
* **author evidence**: Gutenberg `Author:` header, `<meta name=author>`, JSON-LD `author`, `rel=author`/`itemprop=author`, a `By <Name>` byline in the first 1500 chars. A strong author that names a PERSON (not an org word: foundation/library/institute/press/project/university/archive/review/society/committee/administration/staff/editors) and does not match the target → refuse `author_is_other`. A matching author (surname + a given-name token or initial) → attribution `strong`. `host_is_person` = registrable label equals surname / given+surname. `heading` = full person name in `<title>` / first 600 chars of body. Else `none`.
* **voice statistics** over the body words (≤ 40 000 chars): `fp` first-person pronouns (I, me, my, mine, myself, we, us, our, ours) per 1000 words; `tp` third-person (he, him, his, she, her, hers); `nm` the person's surname per 1000 words; quote density (share of characters inside “…”/"…" spans); attribution-line count (`— Name`); biography cues (`was born`, `(1809–1882)`, `died`, `his career/life`) per 1000.
* **Rules, in order**: (1) dropped host → refuse; (2) title cue → refuse; (3) author_is_other → refuse; (4) quote share ≥ 0.25 OR ≥ 3 attribution lines → refuse `quote_farm`; (5) bio cues ≥ 1.5/1000 AND tp > fp → refuse `biography`; (6) tp ≥ 2·fp AND nm ≥ 4/1000 → refuse `third_person_about`; (7) attribution `none` → refuse `no_attribution`; (8) fp ≥ 6/1000 → **own**; (9) attribution `strong` (but fp < 6) → **unsure** `attributed_but_impersonal`; (10) else refuse `no_first_person`.
* Thresholds (6/1000, 4/1000, 0.25, 3, 1.5/1000) are DECLARED from priors, not fitted. Giver: C6 author, 2026-10-06.

## Claims a counterexample refutes
* **F1 (the one that matters): false accepts ≤ 1 of 10 traps; the target is 0.** Every false accept is listed first with the rule that let it through. ≥ 2 refutes "mechanical features suffice to admit a voice".
* **F2: true accepts ≥ 6 of 10 genuine pages** (unsure and refuse both count as misses; unsure is reported separately). ≤ 5 refutes "the gate is usable"; it would be safe but mute.
* **F3 (not host tables alone): the FEATURES-ONLY arm (host/quote-farm/encyclopedia tables off) also has ≤ 2 false accepts.** If more, the safety is the host table, not the text.
* **F4 (not features alone): the HOST-TABLE-ONLY arm (dropped host → refuse, everything else accept) has ≥ 4 false accepts.** If ≤ 3, the features add little and the module is over-built.
* **F5 provenance round-trip**: for every accepted page the stored `sha256` equals the sha256 of the exact text stored, and every banked sentence slices back verbatim from the stored text by its offsets (checked, 100%).
* **F6 integration**: an accepted fetched voice, as a `buildIndex`-shaped archon + `quoteFromBank` bank, goes through fold-chat-voice.js `resonance` + `quoteFromBank` on an on-topic conversation and returns a verbatim quote with offsets (smoke; one case).
* Unreadable pages (fetch fails after Node fetch + Playwright) are listed and excluded from the matrix; if > 4 of 20 are unreadable the run is called INCONCLUSIVE, not passed.
* Pages are cached on first read (`eval/ants/c6/cache/`), so a re-run classifies the same bytes. No threshold is changed after run 1 without saying so; a re-tuned run 2 is labelled post-hoc and gets a fresh held-out set (`battery-holdout.json`, labelled before it is run).

## ADDENDUM 2026-10-06 (after run 1, before run 2) — post-hoc revision, labelled as such
Run 1 (rules above, unmodified; module snapshot `eval/ants/c6/fetchedvoice-run1-snapshot.js.txt`, output `run1-output.txt`, `results-run1.json`) is the PRIMARY result and is never overwritten. Its misses suggested these changes; they are fitted to what run 1 showed, so run 2 on the same battery is NOT evidence. The evidence is a **fresh held-out battery**, `battery-holdout.json` (10 pairs, labelled before it was fetched), classified ONCE by the revised module.
Revisions (v2): (a) a `By <Name>` byline counts only at the START of a line (run 1 read "Get funded by Y Combinator" as an author); (b) a weaker attribution tier `genre_heading`: the person's surname in `<title>`/`<h1>` AND a genre word there (address|speech|letter|essay|lecture|oration|sermon|declaration|inaugural|manifesto|treatise), for the cases where the title carries only "Washington's Farewell Address" or "[King, Jr.]"; (c) `person` may be `{ name, aliases }` (a caller-supplied alias such as a pen-name); (d) author values that are organisations or boilerplate ("Contributors to …", "Privacy", "Cloudflare", "Y Combinator") are not "another person"; (e) a fourth ablation arm `features_blind` (no host tables AND no author_is_other), because in run 1 the features_only arm rejected several traps for the wrong reason (a JSON-LD "Contributors to Wikimedia projects" read as a person).
Claims for the held-out run (refutable): H-F1 false accepts ≤ 1 of 5 traps (target 0); H-F2 true accepts ≥ 3 of 5; the cross-person trap H10 and the about-a-speech trap H6 are refused. Also noted before run 2: battery item G8 served 89 words of page chrome and no essay text (the cached HTML contains no essay), so refusing it is correct and its label was wrong for what the page serves; run 1 keeps the label, the report gives both counts.
