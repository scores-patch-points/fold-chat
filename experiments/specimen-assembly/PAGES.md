# Pages — the tip calculator, by subtraction, model off (criteria frozen before the official run)

Context: the Fold chat app's code lane cannot produce a web page locally (small local models stall on whole pages,
free online models are dead or slow). The rule from the user: weave existing code, never invent a whole page, prefer
editing by subtraction, hold candidate states, let measured marks decide, a model answers only small gaps.

The ask under test (verbatim from the fork session): *single-file HTML tip calculator: bill input, 10%/15%/20% tip
buttons, people input, live tip and per-person text, never negative.*

## What was reused, not rewritten

- **Cutting HTML:** `penelope/organs/html-snip.mjs` (`tokens`, `span`): byte-addressed, balanced, raw-text aware.
- **Cutting CSS:** `khora/native/organs/part-source.js` `cssBlocks`: byte-ranged top-level rules.
- **JavaScript statements:** acorn (vendored earlier).
- **Judging a page by what it does:** a real Chromium via Playwright (a devDependency of the-fold already). Shape of
  the judgement follows `khora/native/organs/build-check.js`: a check that cannot be measured is reported, never passed.
- **A gap as one small ask carrying only its own path:** the convention of `khora/native/organs/talk-build.js`.
- **De-identification of the ask before any model sees it:** `fold-chat-redact.js` `deidentify` with the local Python
  redactor (`scripts/pii/server.py`, port 18795). Fails closed: if it cannot be reached nothing is sent.

## What is authored for the harness (not found in the wild)

Five pages in `pages/`: `tip-suite.html` (the superset: tip calculator plus custom tip, round-up, currency, history,
theme toggle, copy, clear), `bill-splitter.html` (bill, people, per-person; no tip), `counter.html`, `todo.html`,
`contact-form.html`. All written by Claude for this experiment, no external licence; provenance records
`authored-for-harness`. Found pages with real licences are the next step, not this one.

## Development runs that happened before this file was frozen (disclosed)

While building the oracle I ran it on the five pages and ran the subtractor twice. These shaped the oracle:
`P-live` first changed only the bill, the subtractor then deleted the people-input listener and the page stopped
following the people field, so `P-live` now also changes people. I also ran khora's screenshot extractor on a
screenshot of the superset and ran the oracle on its output (recorded in T7 below; that result was seen before this
file was written). No criterion below was tuned against a subtraction result.

## Obligations (browser-checked, `lib/pagecheck.mjs`)

P-title · P-clean (no console/page errors, no external src/href) · P-layout (390 px: no sideways scroll, five controls visible)
· P-bill · P-people · P-tipbuttons (10%, 15%, 20%) · P-compute-15 (100, 1 person → tip 15.00, per person 115.00) ·
P-compute-20-split (100, 2 people, 20% → 20.00, 60.00) · P-live (bill → 200: 40.00, 120.00; people → 4: 60.00; no calculate
button) · P-nonneg-bill (−50) · P-nonneg-people (0 and −3). Eleven in all, each owned by one leaf of the holon tree in
`lib/holons.mjs` (bill-input, people-input, tip-buttons, compute, display, guard, shell).

## Criteria

**T1 — pool evaluation.** `tip-suite` holds 11/11. Every other specimen fails at least one.
`bill-splitter` holds exactly the leaves `bill-input`, `people-input`, `guard`, `shell`.
*Falsified if* `tip-suite` fails any obligation, another specimen passes all, or `bill-splitter`'s held set differs.

**T2 — model-off assembly by subtraction.** With the pool as it is, the assembler picks the superset, deletes byte
ranges only, and the result passes all 11 obligations in Chromium; the receipt's deletions re-applied to the original
bytes reproduce the output's sha256; generated bytes = 0; no model call; output at least 30 % smaller than the input.
*Falsified if* any obligation fails, the receipt does not re-derive, any byte is not from the input, or the saving is under 30 %.

**T3 — what subtraction cannot do (measured, prediction stated).** Of the seven extras (custom tip, round-up, currency
select, history list, theme toggle, copy button, clear button) report which remain. Prediction: the currency select
may remain, because the page reads its value inside an expression and statement deletion cannot rewrite
expressions. *Falsified if* the history list, theme toggle or copy button remain.

**T4 — marks, not names.** Each surviving leaf atom, deleted alone, breaks at least one obligation, so each belongs to
a holon by evidence. *Falsified if* fewer than 90 % of surviving leaf atoms hold up any obligation.

**T5 — the void, defined holonically.** Remove `tip-suite` from the pool. No specimen passes all. The nearest is
`bill-splitter`. The void report names exactly the leaves `tip-buttons`, `compute` and `display` as not held, and no
other. Each void lists its suppliers (with the element ids they live in), its consumers, its unmet obligations with
what was observed, and a seam of at least one statement of the nearest specimen. Every seam statement's text must be
found at its stated byte range in that specimen.
*Falsified if* the void set differs, a held leaf is reported void, a seam is empty, or a seam address is wrong.

**T6 — the asks, and the door.** One ask per void in dependency order (`tip-buttons` before `compute` before
`display`), each at most 2 500 characters as JSON and carrying only its own path, contract, neighbours, seam and
scenarios (not the whole page). Each ask is passed through `deidentify` with the real redactor. The masked text must
parse as JSON and equal the original ask exactly (no slot name, holon id or obligation id altered).
*Falsified if* masking alters any field. *Not evaluated* (neither pass nor fail) if the redactor cannot be reached:
that is the door failing closed, and it is reported as such. No model is called in this experiment.

**T7 — reported, not graded: the screenshot extractor.** khora's screenshot-to-HTML (`cli/screen.mjs --html`) run on
a screenshot of the superset, then the oracle on its output. Seen before this file was written: it passed `P-title`
and `P-clean` only. Reported again in the final run for the record.

**T8 — cost, reported.** Oracle calls, rounds, wall-clock for the subtraction; atoms by kind.

## Known limits, in advance

- Statement and element deletion cannot rewrite an expression, so a feature woven through an expression stays.
- Obligations are the only definition of "the ask": whatever they do not test can be deleted (the `P-live` lesson).
  A tip calculator that satisfies these eleven is not thereby a good one.
- The oracle is one browser at one viewport; the page is judged by eleven scenarios, not by use.
- The superset was written by Claude and so is unusually cooperative (named ids, statement per line).
  Real found pages will be harder to cut.
